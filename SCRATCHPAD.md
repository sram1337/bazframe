## Current focus

The global-source redesign is implemented: `<BAZFRAME_HOME>/sources/<provider>/<source>.json` owns shared activation, profiles hold exact references under `profiles/<profile>/sources/`, and old `source-units/` content is inert. Global add/build are the only build paths. A rebuild activates only after every referencing profile accepts the candidate; global deletion is refused while referenced. The add/build/remove commit points re-enumerate and content-revalidate the complete reference index, while the documented non-cooperating final-syscall race remains bounded. Runtime/Pi reports valid references even when their global target fails and projects only usable active-profile targets; any malformed or raced profile reference namespace withholds all managed sources for that profile while preserving flat skills. CLI source overview and TUI dashboard each capture one bulk reference-index snapshot so all global-source counts, index diagnostics, and health derive from the same inspection. The TUI provides read-only Sources and profile references, retains unavailable references with deterministic diagnostics, and shows Skillbook/all-global-source expandable Skills roots with exact `[-]`/`[+]` markers and indented children; zero-child roots use verified immutable snapshot paths, and invalid reference-index counts are reported as unknown. Follow-up independent review fixes are complete. Validation passes `npm test` (312 unit and 30 integration tests plus pack), `npm run test:real-pi`, `npm run test:tui-terminal:local`, and `npm run test:tui-terminal:linux`. Snapshot GC, migration, singular aliases, provider acquisition, sandboxing, and TUI source mutation remain outside scope.

## Product questions after the Pi slice

The first Pi integration now commits to one global active profile, file-free enabled global policy, project-over-global canonical-path overrides, immediate Agent Skills-compatible profile children, lowercase hyphenated profile IDs, a 1 MiB instruction cap, additive native/profile skills, and deterministic Pi collision aliases.

Runtime-native repository harness material and the active personal profile are separate opaque, provenance-preserving effective layers; deterministic adapter order is transport rather than semantic precedence, and Bazframe performs no semantic contradiction analysis or resolution. Profile duplicate failures retain their flat/source atomicity boundaries. In Pi 0.82, a pre-existing skill-command occupant keeps its name and a colliding profile skill receives the one deterministic, length-bounded runtime-cache alias only when free; occupied aliases fail visibly without fallback. A future adapter must define its behavior and may not silently drop, overwrite, or mutate profile identity. Agent Skills defines no dependency field, so Bazframe adds no inter-skill dependency schema or automation; providers retain shared-resource and runtime-package ownership. Direct Skillbook-backed membership and global managed-source activation are implemented. Profiles refer to global sources; no migration or profile-local fallback exists. Packs, subsets, and export are deferred.
