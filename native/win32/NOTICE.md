# Native Windows provenance

The Bazframe native Windows module is owned, versioned, built, and released by Bazframe.

Windows HANDLE-management, reparse-inspection, and N-API error-bridging techniques were adapted from `@openclaw/fs-safe` 0.7.2 source at tag `v0.7.2` (`e9ab355341ecd47d3c5eeb523c5c8efd25587db9`). That source is Copyright (c) 2026 openclaw and licensed under the MIT License reproduced in `OPENCLAW-LICENSE`.

No OpenClaw package or private runtime API is linked into the Bazframe binary. The notice records source provenance for adapted techniques.

## Native dependency notices

These notices accompany `artifacts/native/win32-x64-msvc/bazframe-win32.node`.
The inventory covers the Windows target-side dependency closure of the pinned
`Cargo.toml` / `Cargo.lock`, including code that optimization may omit; it is not
a claim that every routine in each dependency remains in the binary. Where a
crate permits MIT as an alternative, this distribution selects MIT. libloading
uses ISC. Rust's compiler-builtins has combined terms, reproduced separately below.

The registry archive SHA-256 checksums are recorded in `Cargo.lock`. The license
texts below come from those archives, except the N-API repository license,
recovered at the exact commits in the archives' `.cargo_vcs_info.json`.

Build-time libraries are distinct from this target inventory: `napi-build`,
`napi-derive`, `napi-derive-backend`, `convert_case`, `unicode-segmentation`,
`proc-macro2`, `quote`, `syn`, `semver`, `unicode-ident`, and `futures-macro` run as
build/procedural-macro tools. Their presence in the lockfile does not mean their
implementations are shipped. The N-API notice also covers generated N-API glue;
the Futures notice is shared by futures-macro. `ctor` also has a target-side role
and is included above. The lockfile's `libc` and `cfg-if` are Unix-only in this
crate dependency graph; Rust's separate standard-library use of cfg-if is covered
below. Optional, unselected dependency features are not included in this inventory.

## Rust standard library and runtime

The native producer uses Rust 1.88.0, commit
[`6b00bc3880198600130e1cf62b8f8a93494488cc`](https://github.com/rust-lang/rust/tree/6b00bc3880198600130e1cf62b8f8a93494488cc),
for `x86_64-pc-windows-msvc`. Rust standard-library/runtime code is linked as
needed into the native module. The following notices cover its possible runtime
contributions, rather than every tool distributed with Rust.

Scope and versions were reconciled with the producer's retained
`share/doc/rust/COPYRIGHT-library.html`, installed `rust-std` component manifest,
and that Rust commit's `library/Cargo.lock` and target-specific manifests:

- Rust core, alloc, std, panic/unwind support, and the in-tree Windows import
  support: MIT selection, including the separate backtrace, channel, stdarch,
  portable-SIMD and Unicode notices below.
- cfg-if 1.0.0, hashbrown 0.15.3, rustc-demangle 0.1.24: MIT selection. These are
  standard-library dependencies, independent of Bazframe's crate lockfile.
- compiler_builtins 0.1.158: upstream combined MIT and Apache-2.0 with LLVM
  exception terms; its full license and applicable bundled math notices follow.

The producer's standard-library copyright inventory also lists build tools,
test/proc-macro support and other operating-system targets. That inventory is
not a list of libraries all shipped by this module. In particular, the MSVC
standard-library configuration excludes libc, the Unix unwinder and the
addr2line/object/miniz stack; Rust's in-tree `windows-targets` 0.0.0 is import
support, not a copy of Windows system DLL implementations.

The reviewed native binary imports Windows system DLLs, `VCRUNTIME140.dll`, and
UCRT API-set DLLs dynamically. Those DLLs and the compiler/linker tools are not
bundled in the npm package. This notice does not assert that all toolchain code
is redistributed, or grant rights to separately supplied system components.
